## Review findings and fixes

### Finding 1 — Haversine numeric boundary

The Haversine intermediate value is mathematically in `[0, 1]`, but floating
point can drift slightly outside that interval for extreme coordinates. Both
implementations now clamp it before square roots. Antipodal regression tests
protect the behavior.

### Finding 2 — incomplete ground-truth validation

The first parser version checked expected endpoints and node existence, but did
not prove that every expected edge existed or that the declared cost matched the
path. Java and Rust now traverse the expected path during parsing, reject missing
roads, use checked addition and compare the exact sum with the declared cost.

Both fixes are in commit
`3d19262e3a4f48bbc6eacad408be2c2e6665b3c9` and passed CI run `#13`.

## Architectural decisions made autonomously

1. Use a dependency-free line-oriented fixture for the first Lab.
2. Use integer metre costs to avoid floating-point report ambiguity.
3. Require road cost to be at least straight-line WGS84 distance so the A*
   heuristic remains admissible.
4. Keep the Java and Rust models explicitly fixture-scoped rather than calling
   them production canonical contracts.
5. Defer Gradle/KMP until the first real shared contract module.
6. Treat missing local Rust as a transparent environment limitation and require
   CI validation.
7. Preserve CI failure logs as artifacts instead of weakening gates when the
   first runs exposed documentation casing and formatting differences.

These choices are reversible and do not change product scope.
